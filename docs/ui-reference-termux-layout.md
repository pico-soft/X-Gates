## Мёртвые сервера и разделение живые/все — КАК В ФАЙЛЕ
- **Мёртвый** (пинг не ответил): просто ОТСУТСТВУЕТ в «Живых» (предфильтр). В «Все серверы»
  его пинг = «—» (muted `#777`), скорость `==0` = **«✗» red `#ef5350`**, `<0`/нет = «—» muted.
- Разделение: «Живые серверы (N)» видимая таблица только прошедших; «Все серверы (N)» —
  свёрнутый `<details>` с полным списком.

## Пороги цветов — ИЗ ФАЙЛА (не по памяти!)
**В эталоне НЕТ градаций по числам.** Цвет БИНАРНЫЙ:
- Пинг: `>0` → **green `#69f0ae`**; иначе → **muted `#777`** «—». (В «Живых» всегда green.)
- Скорость: `>0` → **green `#69f0ae`**; `==0` → **red `#ef5350`** «✗»; `<0`/нет → **muted `#777`** «—».
- Прочие: активная плашка/строка green `#1b5e20(44)`; off-плашка red `#b71c1c33`.

> ✅ Расхождение — РЕШЕНО (осознанное отклонение от эталона): Android красит пинг/скорость
> **градиентом по порогам** (пинг 500/1000 мс = зелёный/оранжевый/тёмный; скорость 1/5 Мбит/с),
> а не бинарным зелёным как в эталоне. Elyor выбрал оставить градацию — информативнее.

## Стоп-лист в эталоне (снято с файлов, Промпт 41)

Источник: `xproxy_lib.py` (функции стоп-листа + фильтр), `templates/index.html` (секция), `blacklist.txt`.

**UI (index.html, `<details id="d-blacklist">`, строки 226–234):**
- Заголовок `<summary>` = «🚫 Стоп-лист».
- Чипы слов: `<span class="bl">{{ w }} <a href="/del_blacklist/{{idx}}">✗</a></span>` — слово + красный «✗» для удаления (css `.bl` = серая пилюля `#333`, ссылка `✗` — красная `#ef5350`).
- Форма добавления: `<input name="word" placeholder="Слово">` + кнопка «+».
- Рядом с чипами НИЧЕГО не показано (ни счётчика заблокированных, ни пометки бесполезного правила — это НАШЕ расширение, в эталоне нет).
- Только ОДИН подраздел — слова. Персональной блокировки по серверу в эталоне НЕТ (наше расширение).

**Логика (xproxy_lib.py):**
- `get_blacklist()` (627): читает `blacklist.txt`, каждая строка `.strip().lower()`.
- `check_blacklisted(name)` (650): `any(kw in name.lower() for kw in get_blacklist())` → **подстрока, регистронезависимо**.
- `is_blacklisted_meta(m)` (830): проверяет `check_blacklisted(m["NAME"])` — **только по имени (NAME), не по адресу/HOST**.
- `get_active_servers()` (833): ЕДИНАЯ точка фильтрации (UI/автовыбор/монитор/тесты) — `result = [s for s in result if not is_blacklisted_meta(s)]`. Скрытие «на лету», серверы остаются в хранилище.
- `add_to_blacklist`/`remove_from_blacklist` — дозапись/перезапись файла; веб-хендлеры `/add_blacklist`, `/del_blacklist/<idx>` (xproxy_web.py 326–335) только зовут их и делают redirect.

**Ответы на 4 вопроса (Промпт 41.A):**
1. **Правило** = подстрока (`kw in name`), НЕ слово целиком, НЕ регекс. **Регистр НЕ учитывается** (обе стороны `.lower()`).
2. Проверяется **только по отображаемому имени** (NAME). Адрес/HOST не участвует.
3. **Активный заблокированный сервер:** в эталоне НИКАК не обрабатывается. `add_blacklist` не рвёт и не переключает соединение; `get_current_server` (1006) читает активный конфиг напрямую, НЕ через blacklist-фильтр → активный сервер продолжает работать. Блокировка лишь исключает его из будущих листингов/автовыбора. (Поведение при живом активном → берём из спеки E.)
4. **Предустановленный набор ЕСТЬ:** `DEFAULT_BLACKLIST` (12 слов: москва/россия/санкт-петербург/беларусь/минск/крым + англ. эквиваленты), пишется в `blacklist.txt` при первом запуске, если файла нет (`xproxy_lib.py` 198–199). Т.е. эталон ИЗ КОРОБКИ поставляет RU/BY-стоп-лист.
